# SFTP 验收流程

## 范围

验证文件页面的本地目录浏览、远程目录浏览、目录导航、排序、选择、创建目录、重命名、删除、上传、下载、覆盖确认、传输进度和取消行为。

## 前置条件

- 使用可访问的 SSH 服务器和已绑定的密码、私钥或 SSH Agent。
- 若连接使用密码认证但没有保存密码，文件页面没有可输入的提示符，必须先在该连接的 SSH 终端里输入一次密码**并保持该终端标签打开**（口令只在该连接尚有活跃会话时缓存在内存中供 SFTP 复用），否则会得到“尚未提供登录密码”的提示。
- 主机密钥采用 TOFU：首次连接会记录到 `known_hosts`，之后密钥变更即拒绝。建议先在 SSH 终端完成首次连接并核对指纹，再进入文件页面。
- 准备包含 Unicode 名称、空文件、普通文件和子目录的本地及远程测试目录；性能检查目录应包含较多文件。
- Unix 远端可额外准备命名管道，确认目录浏览会忽略当前模型不支持的特殊文件且不会阻塞。
- 测试账号只能访问测试目录，避免对生产数据执行删除或覆盖。

## 步骤

1. 从“文件”入口选择连接，确认本地和远程两栏均能加载。
2. 断开并重新连接后首次进入文件较多的远程目录，确认只发起一次加载且不会长时间卡住。
3. macOS 首次读取钥匙串时选择拒绝，确认标签进入失败状态；不关闭标签直接再次执行“连接”，确认会重新弹出授权并可继续连接。
4. 钥匙串授权框停留期间确认连接仍显示处理中，但主窗口可重绘且不会进入系统无响应状态。
5. 双击目录、点击路径和上级目录，确认当前路径与列表同步。
6. 点击名称、大小、修改时间表头，确认升降序切换且目录始终排在文件前。
7. 使用单选、Ctrl/Cmd 多选、Shift 范围选择和全选，确认右键操作范围正确。
8. 分别在本地和远程创建目录、重命名并删除，确认刷新后状态一致。
9. 上传和下载单个文件、目录及多项内容，确认覆盖前有确认提示，完成后目标目录刷新。
10. 对大文件传输执行取消，确认任务结束、临时文件被清理且列表不展示临时文件；取消目录上传后额外检查远端目录是否残留已传子文件（当前实现不做远端回滚，见 ADR-002 遗留）。
11. 在网络中断或无权限目录上执行读取和传输，确认页面显示稳定错误提示且应用仍可继续操作。
12. 打开多个 SFTP 标签，分别右键验证“关闭当前标签”“关闭其他标签”和“关闭全部标签”，确认只关闭预期会话且活动标签状态正确；只有一个标签时“关闭其他标签”应禁用。
13. 在大文件传输期间通过右键菜单或标签关闭按钮关闭对应 SFTP 标签，确认先显示取消传输提示；选择取消时标签与传输均保留，选择关闭时传输停止、会话释放。
14. 关闭 SFTP 标签、在连接列表执行断开以及退出应用，确认传输会先停止，进程内 SFTP 会话随之释放，任务管理器中不应残留 `ssh`/`sftp` 子进程（当前实现不再 shell 出系统 OpenSSH）。
15. Windows 上重复步骤 5–13，重点确认密码认证可直接使用已保存口令（不再依赖控制台输入），且目录传输不依赖远端 `tar`。
16. 针对未保存密码的密码认证连接：先直接进入文件页面，确认提示“尚未提供登录密码”；再到 SSH 终端输入一次密码登录成功并保留该标签，返回文件页面确认无需再次输入即可浏览远程目录；随后关闭该连接的全部终端标签，确认已建立的 SFTP 会话仍可继续浏览与传输（SFTP 会话自持连接，不随终端关闭而失效）；最后完全退出应用再进入文件页面，确认提示恢复为“尚未提供登录密码”，且此时必须先回到终端重新输入密码。
17. 在远端目录里创建一个 Linux 合法、Windows 非法的文件名（`touch 'a:b.txt' 'what?.log'`），下载整个目录：Windows 上必须给出明确提示（冒号项报"含有冒号，Windows 会把它当作备用数据流"，问号项报本地写入失败并带系统原文），**不得**静默把内容写进 `a.txt` 的备用数据流；macOS 上两项都应正常下载。
18. 反向验证目录穿越防护：远端条目名一律在拼接本地路径前校验，因此正常的中文名、带空格名、以 `..` 开头（如 `..hidden`）的名字都应能正常下载，只有恰好等于 `.`/`..` 或含路径分隔符的名字才被拒绝。
