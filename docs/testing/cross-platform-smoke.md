# 跨平台基础冒烟测试

## 前置条件

- Node.js 22、pnpm 11、Rust 1.94；
- macOS 安装 Xcode Command Line Tools；
- Windows 安装 Microsoft C++ Build Tools 和 WebView2；
- 在项目根目录完成 `corepack pnpm install`。

## 静态门禁

```bash
corepack pnpm check
corepack pnpm cargo:check
```

记录操作系统、CPU 架构和全部命令结果。失败时不得更新为“平台已验收”。

## 浏览器预览

1. 执行 `corepack pnpm dev`；
2. 打开 `http://127.0.0.1:1420`；
3. 确认应用壳完整显示，状态为 `browser preview`；
4. 缩放至 760px 以下，确认左侧模块栏隐藏、指标改为纵向排列；
5. 控制台不应出现未捕获错误。

## Tauri 运行

1. 执行 `corepack pnpm tauri dev`；
2. 确认窗口可启动、缩放和关闭；
3. 打开 SSH/SFTP 标签后，按住顶部标签栏空白区或左侧导航空白区拖动，确认窗口跟随鼠标移动；在按钮、输入框和具体标签上操作时不得误触窗口拖拽；
4. 顶部状态应变为 `desktop core ready`；
5. TARGET 显示当前 `macos` 或 `windows` 及正确 CPU 架构；
6. TERMINAL 显示 `macos-pty` 或 `windows-conpty`；
7. CREDENTIAL 显示对应系统安全存储；
8. 底部事件计数至少为 1，证明 Command/Event 示例链路均已接通；
9. 关闭窗口后确认进程正常退出。

Windows 还需确认系统原生标题栏及右上角最小化、最大化/还原和关闭按钮均可用，内容区左侧导航不再保留 macOS 交通灯空位。macOS 继续使用系统交通灯覆盖样式。

## 阶段 1 SSH 业务验收

在目标系统准备一个可登录的测试 SSH 主机，并分别准备密码、OpenSSH 私钥和 SSH Agent 三种认证条件。SSH 由应用进程内的 `russh` 实现，不依赖系统 `ssh`/`ssh.exe`，因此记录内容为实际系统版本、CPU 架构、远端 SSH 服务端版本和测试连接标识。

1. 新建连接，验证连接资料、分组名称和排序在重启应用后仍然存在；
2. 使用密码认证并把密码写入系统凭据库，验证可直接打开终端，SQLite 和普通日志中不得出现密码；
3. 使用密码认证但**不保存密码**（连接表单留空密码），验证终端内出现“该连接未保存密码”提示符：输入**完全不回显**（与 `ssh` 一致，屏幕上不出现任何字符或星号），退格与 Ctrl+U 可编辑，方向键不会污染口令，回车后完成登录；
4. 在提示符处验证粘贴：Ctrl+V 粘贴口令后直接回车应能登录成功（不回显，所以以登录结果为判据）；右键粘贴同样生效（应用禁用了 WebView 原生右键菜单，右键即粘贴）；若右键提示“无法读取剪贴板”，记录下来——说明该平台 WebView 拒绝剪贴板读取权限；
5. 粘贴一段带尾随换行的密码，确认直接完成提交而不是把换行并入口令；
6. 在提示符处按 Ctrl+C，确认输出“[已取消连接]”且会话状态变为已关闭，可通过“重新连接”重新提示；
7. 在提示符处故意输入错误密码，确认给出认证失败提示；点击“重新连接”后应再次提示输入而不是沿用错误口令；
8. 用第 3 步登录成功后**保持该标签打开**，新开该连接的第二个标签，确认不追问密码（口令仅在该连接尚有活跃会话时缓存在内存）；
9. 关闭该连接的全部标签后再次连接，确认重新提示输入密码；断线后点“重新连接”同样应重新提示；
10. 使用私钥文件认证：选择一个 2048 位及以上的 RSA `.pem`（Windows 凭据管理器单条上限 2560 字节，正是旧实现在此报"保存系统凭据失败"），确认保存成功并能登录；重新打开编辑弹窗，确认私钥路径已回填；私钥内容只在内存中流转，既不写入 SQLite 与系统凭据库，磁盘上也不应出现任何临时私钥文件；
11. 把第 10 步的连接改成密码登录并保存，再改回私钥登录，确认路径已被清空、需要重新选择文件（避免"已绑定"状态残留）；选一个不存在或不可读的路径保存，确认在保存阶段即报错而不是等到打开终端才失败；
12. 使用 SSH Agent 认证，验证 Unix 下 `SSH_AUTH_SOCK` 与 Windows 下 OpenSSH 命名管道均能取到身份并完成登录；
13. 同时打开两个 SSH 连接，验证标签切换、输入输出隔离和窗口缩放；在标签右键菜单依次验证“关闭当前标签”“关闭其他标签”和“关闭全部标签”，确认后台标签关闭时当前会话不会被切换；
14. 让远程会话主动退出，验证状态变为已关闭并可通过“重新连接”恢复；
15. 配置远程初始路径，验证进入远程 Shell 后工作目录正确；
16. 首次连接新主机后再人为篡改 `known_hosts` 中该主机的密钥，确认重连被拒绝并给出主机密钥变更提示（TOFU：首次信任、变更即拒）；
17. 重命名分组，验证新名称持久化；
18. 删除分组，验证其中连接移动到“未分组”，不会删除连接资料；
19. 在某个用交互口令登录过的连接仍有活跃会话时删除该连接，确认缓存口令立即清除——重新创建同名连接后仍会追问密码；
20. 在仍有 SSH 会话时退出应用，确认进程正常退出且任务管理器中不残留 `ssh` 子进程与临时私钥目录；
21. 验证建连失败的提示能指明阶段与目标：把端口改成一个本机确定无人监听的值，确认约 1 秒内报"拒绝了连接"且提示里带 `host:port`；把主机改成一个不存在的域名，确认报"无法解析主机名"；把主机改成一个安全组/防火墙未放通的地址，确认约 15 秒（而非 30 秒）后报"超时"并提示检查安全组。三种提示必须互不相同，都不得只显示笼统的"连接远程主机超时"。
22. 在远端执行 `for i in $(seq 1 300); do echo "第 $i 行中文输出校验，汉字不得出现乱码"; done`（或 `cat` 一个较大的 UTF-8 中文文件），确认输出中没有任何 `�`——读取按 8 KiB 分块，多字节汉字必然被切开，解码状态必须跨读取保持；
23. 打开同一连接的两个标签，在其中一个里执行命令，确认输出只出现在该标签，另一标签不出现开场信息或命令回显（事件按 `terminalId` 严格过滤，不按 `connectionId` 兜底）；
24. 对任一会话点"重新连接"后反复切换标签，确认其它标签的会话仍然存活：正在运行的 `top`/`tail -f` 不中断，用交互口令登录过的连接也不会被重新追问密码；
25. 把 `known_hosts` 中该主机那一行改成格式损坏的内容（例如截断 base64），确认连接被**拒绝**并提示"无法校验主机密钥"，而不是当作校验通过放行。

只有上述业务项全部通过，能力矩阵中的对应平台状态才能更新为“已验收”。浏览器预览和静态门禁不能替代这组测试。

## 本地终端验收

1. 在没有任何会话时点击“打开本地终端”，确认出现“本地终端”标签并显示系统默认 Shell 提示符；
2. 输入 `echo NOCTERM_LOCAL_TERMINAL`，确认命令和输出只出现在当前标签；
3. 点击标签栏末尾“+”，确认新增“本地终端 2”，两个本地会话可独立输入和切换；
4. 在已连接会话里复制一段文本后分别用 Ctrl+V 和右键粘贴，确认内容各自只出现一遍（不能粘贴两次），SSH 会话内同样验证一次；
5. 缩放窗口，确认当前 PTY 尺寸随 xterm 更新，长行不会持续使用旧列宽；
6. 通过关闭按钮和标签右键菜单关闭一个或多个标签，确认仅对应 Shell 子进程退出，其他本地或 SSH 会话继续工作；
7. 在 Shell 中执行 `exit`，确认标签状态变为已关闭，并可通过“重新连接”重新创建本地 Shell；
8. 退出应用，确认所有本地 Shell 子进程被回收；
9. macOS 记录实际默认 Shell；Windows 默认验证 PowerShell（优先 `pwsh.exe`、其次 `powershell.exe`），未安装 PowerShell 时再验证 `COMSPEC` 对应的 CMD/ConPTY 行为；
10. 输出一大段中文（例如 `Get-Content` 一个 UTF-8 中文文件，或 `for` 循环打印数百行中文），确认没有 `�`——本地 PTY 与 SSH 通道共用同一套跨读取的 UTF-8 拼接逻辑；
11. Windows 专项：启动应用与点击“打开本地终端”的瞬间盯住屏幕，**不得**闪出任何黑色控制台窗口。应用不再 spawn `ssh -V` 与 `where.exe` 做探测，若仍看到闪窗说明有新的子进程调用没走 `CREATE_NO_WINDOW`。
12. 复制快捷键（本地终端与 SSH 会话各验一遍，Windows 必测）：用鼠标选中若干行输出，分别用 `Ctrl+C`、`Ctrl+Shift+C`、`Ctrl+Insert` 复制，再粘贴到记事本核对内容，并确认复制后选区消失；
13. 复制不能吃掉中断信号：执行一个长时间运行的命令（如 `ping -t 127.0.0.1` 或远端 `tail -f`），在**没有选区**时按 `Ctrl+C`，确认命令被中断而不是被当成复制；紧接着选中一段文本按 `Ctrl+C` 复制，再按一次 `Ctrl+C`，确认第二次恢复为中断（选区已在第一次复制后清空）；
14. SSH 口令提示符处按 `Ctrl+C`，确认仍然输出“[已取消连接]”而不是被复制拦下；按 `Ctrl+Shift+C` 确认既不复制出任何内容，也不会打断提示；
15. 若终端里出现“[无法写入剪贴板]”，记录平台与 WebView 版本——说明该环境同时拒绝了异步剪贴板 API 与 `execCommand('copy')` 兜底。

只有在目标系统完成上述交互后，才能把本地终端更新为对应平台“已验收”。
