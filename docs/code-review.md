# Code Review 规范

审查目标是发现会影响正确性、安全性、可维护性和跨平台行为的问题。先报告高风险问题，再处理命名和风格；自动化工具能够确定的问题不重复占用人工审查重点。

## 1. 问题级别

- **P0 阻断**：凭据泄露、任意命令执行、不可恢复数据损坏、默认关闭安全校验。
- **P1 严重**：主流程错误、资源泄漏、竞态、死锁、错误目标执行、跨平台核心功能不可用。
- **P2 一般**：边界破坏、错误语义不稳定、测试缺失、明显维护风险。
- **P3 建议**：不影响当前正确性的可读性或局部简化。

没有可验证影响的问题不作为阻断项。每条 Finding 必须包含文件位置、触发条件、用户/系统影响和最小修复方向。

## 2. 通用检查

- 变更是否匹配需求，是否混入无关重构或未来设计；
- 是否覆盖成功、失败、取消、超时和资源清理路径；
- 是否吞掉错误、返回伪成功或依赖不稳定错误文本；
- 新增公共接口是否必要，是否出现循环依赖或万能模块；
- Bug 修复是否有能在修复前失败的回归测试；
- 注释是否解释意图和边界，文档是否与实际状态一致；
- 最终报告的验证声明是否有对应命令或运行证据。

## 3. Nocterm 高风险检查

### 终端与进程

- session/task ID 是否唯一并绑定正确终端；
- open/write/resize/close/output/exit 顺序是否存在竞态；
- 取消、窗口关闭和异常退出后是否释放 PTY、进程与监听器；
- exit code、timeout 和用户取消是否被准确区分；
- 输出缓冲、截断和背压是否可能耗尽内存。

### SSH/SFTP

- 主机密钥首次确认和变化是否安全处理；
- 密码、私钥、SSH Agent、ProxyJump 和非标准端口是否保持语义一致；
- 远程路径是否安全转义，是否可能命令注入或越权删除；
- 上传/下载取消后临时文件是否清理，覆盖操作是否明确；
- macOS 与 Windows 的进程、路径、编码和错误行为是否分别验证。

### 数据与凭据

- SQLite Migration 是否可从每个受支持版本升级，失败是否保持原数据；
- 数据库是否只保存凭据引用；
- 明文凭据是否可能进入参数日志、事件、崩溃报告或测试快照；
- 凭据保存与数据库写入部分失败时是否可恢复；
- 删除连接时凭据和运行中任务的处理是否明确。

### IPC 与 UI

- Rust DTO 与 TypeScript 类型是否同步；
- Command 是否只执行授权能力，参数是否在 Rust 边界重新校验；
- Event 订阅是否去重并在组件/会话结束时解除；
- UI 是否只依赖稳定错误码，加载、空状态、错误和重试是否完整；
- 浏览器预览降级是否被误认为桌面功能可用。

## 4. 审查结论

结论必须说明：

1. 是否存在阻断问题；
2. 自动检查和真实运行覆盖到什么范围；
3. 哪些平台、协议或失败路径仍未验证；
4. 无 Finding 时仍需指出剩余验证风险，不能暗示代码绝对正确。
