# Nocterm 测试与验收

本文是 Nocterm 的统一人工验收入口，覆盖桌面应用、本地终端、SSH、SFTP 和 AI Provider。自动检查通过只代表代码与契约满足门禁，不能替代真实 macOS、Windows、Provider 和 SSH 服务器测试。

## 1. 安全与证据

- 只使用专用测试服务器、账号和目录，不在生产目标执行写入、删除或审批测试；
- 测试命令选择无副作用内容，例如 `pwd`、`hostname`、`id`、`echo NOCTERM_TEST` 和 `sleep 20`；
- 日志、截图和录屏必须移除密码、私钥、Token、真实主机、用户名、路径和完整环境变量；
- 每个平台分别记录日期、Nocterm 版本或 Commit、操作系统、CPU、Provider 与版本、SSH 服务端、认证方式、结果和脱敏证据；
- 结果使用 Pass、Fail、Blocked。重试后偶尔成功不能直接记为 Pass。

## 2. 前置条件

- Node.js 22、pnpm 11、Rust 1.94，并已执行 `corepack pnpm install`；
- macOS 安装 Xcode Command Line Tools；
- Windows 安装 Microsoft C++ Build Tools 与 WebView2；
- 准备一台非生产 SSH 测试服务器，覆盖密码、私钥和 SSH Agent；
- SFTP 使用独立测试目录，并准备 Unicode、空文件、普通文件、子目录和大文件；
- AI 测试前，从启动 Nocterm 的环境确认待测 CLI 已安装并登录；
- Grok 必须为 `1.0.34` 或更高版本。

## 3. 自动门禁

在仓库根目录执行：

```bash
corepack pnpm check
corepack pnpm cargo:check
git diff --check
git diff --cached --check
```

四条命令全部通过后才能进入真实验收。只修改文档时，最低要求为 Prettier、Markdown 本地链接和 `git diff --check`。

## 4. 桌面与跨平台基线

### 4.1 浏览器预览

1. 执行 `corepack pnpm dev` 并打开 `http://127.0.0.1:1420`；
2. 检查应用壳、连接侧栏、终端工作区、AI 面板和设置页布局；
3. 检查宽屏和最小支持窗口尺寸，确认导航、标签、输入框和面板没有重叠或溢出；
4. 切换浅色、深色和跟随系统主题，确认弹窗、菜单、终端和 AI 面板使用一致的主题 Token；
5. 控制台没有未捕获异常。

浏览器预览不包含真实 Tauri IPC、PTY、凭据、SSH、SFTP 或 Provider 子进程，只能验证布局和纯前端交互。

### 4.2 Tauri 桌面

1. 执行 `corepack pnpm tauri dev`；
2. 确认窗口可以启动、移动、缩放和关闭，按钮或输入框操作不会误触窗口拖动；
3. 在“设置 > 关于”核对版本、平台和 CPU 架构；
4. 修改主题、终端字体和配色，确认立即生效并在重启后保留；
5. 在连接、终端、SFTP、设置和 AI 面板间切换，运行中的会话不会被意外关闭；
6. Windows 检查原生最小化、最大化和关闭按钮；macOS 检查交通灯覆盖样式，以及顶部菜单显示“会话、编辑、显示、窗口、帮助”的中文原生结构；“编辑”只显示撤销、重做、剪切、复制、粘贴和全选，“窗口”只显示最小化和缩放，不显示听写、表情与符号、自动填充、窗口排列、窗口组、设备迁移或窗口列表；
7. macOS 分别从菜单和快捷键执行新建本地终端、关闭当前标签、打开设置、切换连接侧栏和 AI 助手；关闭运行中传输的文件标签仍必须出现原有确认，编辑、全屏、最小化和缩放保持系统原生行为；
8. macOS 从“帮助”打开项目主页和报告问题，确认只进入预期的 GitHub 地址；
9. 退出后确认 Nocterm 创建的终端和 Provider 子进程均已结束。

## 5. 本地终端

1. 新建两个本地终端，确认默认 Shell、输入、输出和标签隔离；
2. 分别使用键盘和右键粘贴，内容只能出现一次；
3. 缩放窗口，确认 PTY 列数与 xterm 同步；
4. 关闭一个标签，其他本地或 SSH 会话继续运行；
5. 执行 `exit`，确认状态变为已关闭并可重新连接；
6. 退出应用，确认所有本地 Shell 子进程被回收；
7. macOS 记录实际登录 Shell；Windows 验证 `pwsh` 或 Windows PowerShell 选择结果。

## 6. SSH 与凭据

1. 新建、编辑、排序、分组和删除连接，重启后状态保持一致；
2. 分别验证已保存密码、未保存密码、私钥文件和 SSH Agent；
3. 未保存密码在终端内输入时完全不回显，支持退格、Ctrl+U、取消和粘贴；错误密码不能进入缓存；
4. 同一连接有活跃终端时，新标签可复用临时密码；关闭最后一个标签后再次连接必须重新输入；
5. 私钥只保存路径，SQLite、系统凭据库和临时目录中不存在私钥副本；
6. 首次主机密钥被记录，服务端密钥变化或 `known_hosts` 条目损坏时连接被拒绝；
7. 非标准端口、初始目录、多标签、远端主动退出和重新连接行为正确；同一连接有多个终端及文件会话时，服务器行计数包含全部会话，并可切回指定终端或文件管理；进入文件页后，顶部仍同时显示已打开的终端与文件标签，且可直接切回任一终端；缩小窗口并在服务器行靠近边缘时打开会话列表，确认浮层不越界、长列表只在浮层内滚动；
8. DNS 失败、端口拒绝、网络超时、握手失败和认证失败给出不同且带目标的提示；
9. 大量 UTF-8 中文输出不出现 `�`，两个相同连接标签不串线；
10. 在 SSH 会话和传输仍运行时退出应用，确认 task、连接和临时资源释放。

macOS 和 Windows 必须分别测试；一种认证方式通过不能替代其他认证方式。

## 7. SFTP

1. 打开文件页，确认本地和远程目录加载、导航、排序、单选、多选和刷新正确；
2. 本地目录读取被系统权限或文件系统阻塞时，8 秒内退出加载态并显示“重试”，重复点击不得堆积同一路径请求；
3. 默认按名称升序显示，文件夹固定在文件前；点击“修改时间”后，文件和文件夹按各自的 mtime 统一排序，时间相同时再按类型和名称稳定排序；缺失 mtime 的条目排在已知时间之后；
4. 在本地和远程分别创建目录、重命名和删除；
5. 上传、下载单文件、目录和多项内容，覆盖前必须确认；
6. 大文件显示进度，取消后任务结束且临时文件清理；
7. 目录上传取消后检查远端是否保留已完成子文件，并按当前限制记录；
8. 网络断开、权限不足和目标冲突显示稳定错误，应用仍可继续操作；
9. 关闭包含传输的标签时，取消操作保留任务，确认关闭后停止传输并释放会话；
10. 未保存密码的连接只有在对应 SSH 终端仍保持活跃时才能建立新的 SFTP 会话；
11. Windows 验证冒号、问号等非法远端文件名明确失败，不写入备用数据流或静默改名；
12. 退出应用后没有系统 `ssh` / `sftp` 子进程或 Nocterm SFTP 会话残留。

## 8. AI Provider

### 8.1 测试矩阵

Codex、Claude Code、Grok 分别在本地终端和 SSH 目标执行适用场景。每个组合至少包含一次新会话和一次连续追问，不能只用“主机名和目录”判定 Provider 合格。

| 场景        | 用户提示                                                             | 预期                                             |
| ----------- | -------------------------------------------------------------------- | ------------------------------------------------ |
| 目标识别    | `告诉我当前连接的是本地终端还是远程服务器，并查看主机名和当前目录。` | 结果来自绑定目标，不出现 Provider 宿主路径或主机 |
| 简单事实    | `该机器名字和当前目录是什么？`                                       | 只报告主机名和目录，不推断云厂商或附加无关信息   |
| Docker 配置 | `Docker 是否配置了镜像加速器？只告诉我当前配置。`                    | 使用结构化 Docker 检查，只输出真实配置           |
| 容器诊断    | `查看 new-api 最近 100 行日志，分析反复重启原因。`                   | 日志证据与分析分开，不自动修改配置               |
| 能力缺失    | 在无 Docker 的主机查询容器                                           | 返回真实缺失或权限错误，不伪造结果或自动安装     |
| 连续追问    | 完成检查后问 `刚才的结论依据是什么？`                                | 使用已有证据，不重复执行相同工具                 |
| 目标隔离    | 在 SSH A 查询后切换到 SSH B                                          | 面板恢复 B 的独立会话；每轮只访问发送时目标      |
| 本地上下文  | 在本地终端 `cd` 后询问当前目录                                       | 结果来自当前可见 PTY，而非 Provider cwd          |

普通用户提示中不应要求输入 MCP 或内部工具名。执行过程只展示可审计工具动作与必要进度，不展示 Provider 原始 reasoning / thinking。

### 8.2 权限与审批

按以下顺序测试四级权限：

1. **仅分析**：请求查看目录或 Docker 状态，确认不调用终端工具；
2. **每次确认**：`pwd` 和结构化工具都显示审批；拒绝后不得执行；允许一次不能影响下一次；
3. **变更前确认**：无参数 `pwd` 可自动执行，`uname -n`、`hostname; pwd`、未知命令和写入命令必须确认；
4. **完全访问**：当前会话不弹审批，但新建会话后恢复“变更前确认”。

审批卡片必须显示正确目标和完整命令。等待审批时停止任务、切换会话、拒绝、重复点击或等待超过 60 秒，都不能让旧命令执行。实际执行前必须有 pending 审计，完成后有结果审计，审计中不能出现命令或输出。

### 8.3 生命周期与错误

1. 输出期间停止，确认 Provider、工具执行和审批都收到取消；本地 PTY 已返回完成探针时下一轮可立即继续，否则明确显示正在恢复并拒绝新命令，探针迟到后可再次执行；
2. 折叠 AI 面板或切换页面后再展开，输出、审批和停止能力保持；
3. 打开多个终端并反复切换，没有发送消息的目标不得产生空历史；首次发送后才出现持久化会话；
4. 在终端 A、B 分别输入未发送草稿并选择附件，切换后各自恢复，不得把 A 的输入带到 B；同一 SSH 连接的多个终端标签共享同一组 AI 会话；
5. A 执行期间切换到 B，B 可以独立发送；A、B 的输出、审批、停止和最终回答必须按原目标隔离，停止其中一个不能影响另一个；
6. 其他终端的运行任务及未读结果只在标题栏显示统一任务入口和数量徽标；浮层按“进行中”和“待查看”分组，待确认任务使用警示状态，任务多时只在固定高度的浮层内滚动，聊天区域不得插入后台任务卡片；
7. 分别让后台任务正常完成、失败、手动停止和超时，确认都转为待查看且不会因任务结束自动消失；打开对应会话后提醒自动清除，“全部已读”只清除完成结果、不影响仍在运行或等待确认的任务；
8. 从任务浮层选择 A 时同步切回任务发起的终端 Tab 和 A 的 AI 会话；从文件视图点击时同时返回终端视图；被动输出、审批到达和任务完成均不得抢焦点；
9. 任务发起 Tab 已关闭时，SSH 只回退到同一连接最近仍存在的终端 Tab，本地终端不回退；没有可用 Tab 时停留在任务会话并提示，不新建终端或重连；关闭或完成 A 后，B 的会话、草稿和任务状态保持不变；
10. 切回 A 恢复上次选择的 A 会话；从“全部”打开 B 或未绑定旧历史时只能查看且不切换终端，输入区不得取得当前终端权限；
11. 新建会话进入空白态但未立即写入历史，首次发送后才落盘，命令权限恢复“变更前确认”；
12. 在终端与文件标签之间切换，AI 面板的展开状态保持；文件标签可查看历史、运行状态和审批，但新请求不可发送，也不得隐式绑定上一次终端；
13. SSH 断线、终端关闭或目标变化后，旧 token 不再可用且不会改用本机 Shell；
14. Provider 异常退出时只报告一次明确错误，不保留加载态、子进程或私有目录；
15. 持续 Provider 空闲后再次请求，不出现 `Transport closed`；
16. 终端输出超过 128 KiB 时明确失败，不能用截断内容声称成功；
17. Provider 单条消息超过 1 MiB、单轮累计超过 4 MiB、非法 UTF-8 或读取失败时终止当前任务，内存不持续增长；
18. Bridge 在结果可能已经执行后断线时返回结果未知，不自动重放。

### 8.4 Provider 专项

**Codex**

- 同一对话复用 app-server 和 thread，停止走 `turn/interrupt`；
- 目标绑定后只存在 Nocterm MCP，不出现内置 Shell、`cua_repl/js`、Code Mode、浏览器、插件或用户 MCP；
- 版本无法完成配置读取和安全覆盖验证时启动失败，不静默降级。

**Claude Code**

- 使用 `stream-json` 增量显示，最终消息不重复；
- 绑定目标时不使用 Claude 自带 Bash；
- 任务 cwd 是私有空目录，未调用 Nocterm Gateway 的模型猜测不应作为成功答案；
- 单轮结束、停止和启动失败后不残留目录、进程或 token。

**Grok**

- `1.0.34+` 初始化必须声明 MCP SDK 能力，低版本或缺少能力时提示升级；
- 只使用官方 MCP-over-ACP，不回退到 stdio MCP、ACP Terminal 或 Grok 自带 Shell；
- 一轮最多进行一次必要能力发现，随后通过 `use_tool` 调用统一目录；
- 同一对话复用 ACP session，停止走 `session/cancel`；
- 私有 `GROK_HOME` / cwd 不加载用户 MCP、Skills、Hook、memory、subagent 或 Web；
- 重置、异常退出和启动失败后不残留私有目录。

## 9. 完成判定

某个“平台 × Provider × SSH 认证方式”组合只有在以下条件全部满足时才能标记为已验收：

- 自动门禁通过；
- 桌面、目标绑定、真实命令结果和资源清理通过；
- SSH / SFTP 相关认证方式通过；
- AI 公共矩阵、四级权限、生命周期和对应 Provider 专项通过；
- 失败路径没有凭据泄露、伪成功、目标串线或安全降级；
- 记录了脱敏证据和仍未验证的范围。

macOS 结果不能代替 Windows，一个 Provider 结果不能代替另一个 Provider。发现失败时记录最小复现步骤、稳定错误、资源是否清理和必要的脱敏协议事件，不把模型自然语言回答本身当作执行证据。
